# kpirank — 离线 KPI 分组排行库

从本地 CSV 载入业务明细，由调用方在载入后任选 1–3 个维度执行分组排行，
找出平均指标（如平均订单金额）最高的分组组合。全程流式处理 + 磁盘分桶，
峰值驻留内存远低于 128 MiB。

## 能力

- `Load(csvPath, metric)`：流式解析 CSV（合法 UTF-8、含表头、列名唯一），
  校验指标列（有符号 64 位整数或空值）与单元格长度（≤256 字节），
  在源文件旁生成派生数据文件 `<源文件>.kpirank`。
- `(*Dataset).Query(Query{Dimensions, Limit})`：任选 1–3 个维度列
  （指标列除外），返回前 `Limit`（1–10000）个分组，分组不足时全部返回。
  维度在载入完成后才选择，任意组合均可查询。

## 用法

```go
ds, err := kpirank.Load("orders.csv", "amount") // amount 为指标列
if err != nil { /* ... */ }
defer ds.RemoveDerived() // 不再需要时删除派生文件

res, err := ds.Query(kpirank.Query{
    Dimensions: []string{"region", "product"}, // 1–3 个维度
    Limit:      100,
})
for _, g := range res {
    // g.Key []string  维度值元组（与查询维度同序）
    // g.Count int64    有效计数（指标非空的记录数）
    // g.Rows int64     组内总记录数（含指标为空的记录）
    // g.Sum *big.Int   有效指标总和（可超 64 位，精确）
    // g.Avg *big.Rat   平均值 = Sum/Count；全部指标为空时为 nil
}
```

## 语义

- 分组依据 CSV 解码后的维度值元组：空字符串是有效维度值，不去除空白、
  不合并大小写，不同元组绝不混组。
- 空指标不参与有效计数/总和/平均值，但所在记录仍建立对应分组；
  全部指标为空的组 Count=0、Sum=0、Avg=nil。
- 排序：平均值降序（`big.Rat` 精确比较，无舍入）；精确并列时按维度元组
  逐项 UTF-8 字节序升序；空平均值排在所有非空之后，组间同样按键序排列。
- 结果与行序无关：同一批记录任意重排，排行完全一致。

## 实现要点

- 载入：单次流式扫描，派生文件按列存放量长前缀二进制记录，内存占用 O(1)。
- 查询：流式读取派生文件，按维度键 FNV 哈希分 256 个磁盘桶；逐桶在内存
  中聚合（`map` + `big.Int` 累加），每桶仅约 分组数/256；跨桶用容量为
  Limit 的堆维护前 K 名。临时桶文件查询结束即清理。
- 仅依赖 Go 标准库，无任何外部服务与端口监听。

## 测试

```sh
go test ./...          # 全部测试（含规模测试）
go test -short ./...   # 跳过规模测试
```

- `TestSmallRank`：小规模随机数据对照独立全量精确计算，覆盖重复分组、
  空指标、空字符串维度、大小写与空白敏感。
- `TestRowOrderInvariant`：同一批记录重排后结果完全一致。
- `TestBigSumsAndNearAvg`：总和超出 int64、平均值相差 0.5 个单位
  （float64 无法区分）时名次与并列顺序正确。
- `TestEmptyMetricGroups`：全空指标组的统计与排名位置。
- `TestValidation`：非法指标、重复列名、超长单元格、非法查询参数。
- `TestScale`：50 万行 / 45 万分组 / 单组键 768 字节；前期垫底的组因
  文件末尾记录登顶，开局榜首因后续记录跌出榜单；核对最终排名并报告
  峰值内存与耗时。本机实测：载入+查询约 1.3 s，峰值驻留内存约 28 MiB。
