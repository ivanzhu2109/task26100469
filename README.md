# kpirank

离线 KPI 分组排行库（Go）。从本地 CSV 载入业务明细到本地文件存储，
载入完成后由调用方任选 1~3 个维度执行分组排行，按平均指标降序返回前 N 组。

## 能力

- `LoadCSV`：载入本地 CSV（合法 UTF-8、含表头、列名唯一），原始数据与派生
  元数据写入指定目录下的本地文件（`rows.bin`、`meta.json`）。
- `GroupRank`：按调用方指定的 1~3 个维度列分组，返回前 N 组的有效计数、
  精确总和（`big.Int`）与精确平均值（`big.Rat`，全空指标组为 `nil`）。

## 快速开始

```go
package main

import (
	"fmt"
	"kpirank"
)

func main() {
	// 载入：指定数据目录、CSV 路径、指标列名
	d, err := kpirank.LoadCSV("/tmp/mydata", "orders.csv", "amount")
	if err != nil {
		panic(err)
	}
	defer d.Cleanup() // 关闭并删除数据文件；保留文件请用 d.Close()

	// 排行：维度在载入后选择，1~3 个，topN 范围 1~10000
	res, err := d.GroupRank([]string{"customer", "product"}, 100)
	if err != nil {
		panic(err)
	}
	for i, g := range res {
		avg := "<nil>"
		if g.Avg != nil {
			avg = g.Avg.RatString() // 精确分数，如 "20000001/2"
		}
		fmt.Printf("#%d key=%v count=%d sum=%s avg=%s\n",
			i+1, g.Key, g.Count, g.Sum.String(), avg)
	}
}
```

## 规则说明

- 指标列：有符号 64 位整数或空值；空指标不参与计数/总和/平均值，
  但所在记录仍建立对应分组。全部指标为空的组：计数与总和为零，平均值为 `nil`。
- 分组键：CSV 解码后的维度值元组；空字符串是有效维度值，不去除空白、
  不合并大小写，不同元组绝不混组。
- 排序：平均值降序；精确相等时按维度元组逐项 UTF-8 字节序升序；
  空平均值排在所有非空平均值之后，空平均值组之间同样按元组字节序。
- 精确性：总和用 `big.Int`（可超 int64），平均值用 `big.Rat` 无损表达，
  排序不发生数值舍入；结果与行序无关。

## 约束与限制

- 单份数据：最多 500000 行、100 列、1 GiB；单单元格最多 256 字节。
- 一次查询：1~3 个维度，topN 1~10000；分组不足时全部返回。
- 查询维度在载入完成后才选择，支持任意维度组合。
- 调用串行执行；不提供文件刷新、并发调用与异常退出恢复。

## 实现要点

- 载入：流式解析 CSV，行式编码顺序写入 `rows.bin`，元数据写 `meta.json`。
- 查询：扫描行存储生成 (分组键, 指标) 对，键经保序编码（字节序即元组序），
  外部排序（16 MiB 顺串 + k 路归并）后流式聚合，用大小为 topN 的堆取前 N。
- 内存：全过程流式处理，峰值驻留内存远低于 128 MiB（规模测试实测约 61 MiB）。

## 测试

```sh
go test ./...              # 全部测试（含规模测试，约 10 秒）
go test -short ./...       # 跳过规模测试
go test -run '^TestScale$' -v .   # 仅规模测试，报告峰值内存与耗时
```

测试覆盖：

- 小规模完整排名与独立全量精确计算一致：重复分组、空指标、行序变化、
  1~3 个维度、topN 超过分组数、平局字节序、参数校验。
- 数值精确性：总和超出 int64、平均值极接近但不相等（float64 无法区分）、
  负数大总和、分数平局并列。
- 多顺串归并：调小顺串预算强制外部排序多路归并，结果仍与参考一致。
- 规模测试：500000 行 × 100 列 ≈ 1 GiB、450000 个分组；文件末尾记录让
  前期靠后的 100 个组进入榜首，早期榜首因后续记录跌出榜单；子进程实测
  峰值内存约 61 MiB（限制 128 MiB），载入+查询约 3.3 秒（限制 120 秒）。
